1. Context

CRM is building Hotel Folio / Room Invoice generation (Mode C of CR-014). When a hotel guest checks out, CRM generates a mobile-friendly invoice (HTML + PDF) covering:

  • Room charges (nights × rate)
  • F&B charges (food ordered during stay, grouped by day)
  • Taxes, discounts, grand total

This invoice is sent to the guest via WhatsApp (einvoice_link variable in send_bill template) and also accessible via a public URL.

Current state: POS sends food items, customer data, and a room_info struct — but it only has 3 fields (room_price, advance_payment, balance_payment). We need 4–7 more fields to generate a proper hotel folio.

2. Current room_info (what POS sends today)

{ "room_info": { "room_price": 1000.0, "advance_payment": 500.0, "balance_payment": 500.0 } }

Sent inside POST /api/pos/orders payload. Only 1 tenant (sunildev/R558) currently populates it. Palm House (R541) uses a "Check In" item at ₹0 as a workaround.

3. Requested Fields

P0 — Critical  Blocks folio generation

#FieldTypeExampleWhy Needed
1 room_number string "305", "Deluxe 12", "Villa A" Human-readable room ID on folio header. Currently CRM only gets table_id (POS internal numeric ID like 4708) — meaningless to guests.
2 check_in string (ISO date) "2026-01-14" Folio header: "Check-in: 14 Jan 2026". Currently CRM derives from first item's serve_at — unreliable.
3 check_out string (ISO date) "2026-04-01" Folio header: "Check-out: 01 Apr 2026". Currently CRM derives from order_updated_at — unreliable.

P1 — Important  Improves folio quality

#FieldTypeExampleWhy Needed
4 nights integer 3 "3 Nights" on folio. CRM can derive from check_in/check_out if missing, but POS may have actual booked value.
5 room_type string "Deluxe Room" Shown on folio: "Room Type: Deluxe Room". Helps guest identify their booking.
6 rate_per_night float 3000.0 Enables itemized room charge: "3 nights × ₹3,000 = ₹9,000". Currently only lump-sum room_price.

P2 — Nice to Have

#FieldTypeExampleWhy Needed
7 guest_count integer 2 "Guests: 2" on folio header. Minor cosmetic detail.

4. Proposed Expanded room_info

{ "room_info": { "room_price": 9000.0, "advance_payment": 5000.0, "balance_payment": 4000.0, "room_number": "305", ← NEW (P0) "check_in": "2026-01-14", ← NEW (P0) "check_out": "2026-01-17", ← NEW (P0) "nights": 3, ← NEW (P1) "room_type": "Deluxe Room", ← NEW (P1) "rate_per_night": 3000.0, ← NEW (P1) "guest_count": 2 ← NEW (P2) } }
Backward Compatible: All new fields are optional. CRM handles null/missing gracefully. Existing fields unchanged. No new endpoint, no new header — just additional keys inside the existing room_info object.

5. Full Payload Example

The room_info struct is sent inside the existing order webhook:

POST /api/pos/orders { "pos_order_id": "869143", "restaurant_order_id": "010585", "order_type": "pos", "order_amount": 15000.0, "cust_name": "Ms. Jamie Finlayson", "cust_mobile": "+351927605555", "payment_method": "card", "items": [ {"item_name": "Cappuccino", "item_qty": 1, "item_price": 160.0}, {"item_name": "Eggs Benny", "item_qty": 1, "item_price": 350.0} ], "room_info": { "room_price": 9000.0, "advance_payment": 5000.0, "balance_payment": 4000.0, "room_number": "305", "check_in": "2026-01-14", "check_out": "2026-01-17", "nights": 3, "room_type": "Deluxe Room", "rate_per_night": 3000.0, "guest_count": 2 } }

check_in / check_out missingCRM derives from item serve_at dates (less reliable)
nights missingCRM derives: check_out - check_in in days
rate_per_night missingCRM shows lump-sum room_price without per-night breakdown
room_type missingOmitted from folio
guest_count missingOmitted from folio

7. Palm House "Check In" Item Pattern

Palm House (R541) currently uses a menu item called "Check In" at ₹0 to mark hotel guests instead of room_info. This works for guest identification but lacks room charge data.

Recommendation: Palm House should also adopt room_info. CRM supports both patterns during transition:
• Pattern A (room_info struct): Full hotel folio with room charges
• Pattern B ("Check In" item): F&B-only guest folio (no room charges)
Once Palm House switches, Pattern B becomes legacy.
