## 5. Watch-Out Rules Learned This Session

### 5.1 `search_replace` on Python files
Earlier fork lost a `@router.post` decorator via a too-broad `search_replace`.
Same near-miss with `PRD.md` this session (fixed). Always include enough
surrounding context in `old_str` to guarantee the replacement doesn't strip
adjacent code/headers.

### 5.2 MongoDB authentication
The prod MongoDB has both a `mygenie` DB (with data) and a `mygenie_db` DB
(empty legacy). Env `.env` must have `DB_NAME=mygenie`. Read-only user
`mygenie_mongo_readonly` was used at start of session — `server.py` has
try/except around all `create_index` calls to survive that.

### 5.3 Auth cookie / JWT storage
Frontend `AuthContext` stores JWT under localStorage key `"token"` but the
backend response field is `access_token`. When scripting login for automation:
```js
localStorage.setItem('token', response.access_token)
```
NOT `response.token` (doesn't exist).

### 5.4 AuthKey returns duplicate LogIDs
Confirmed empirically on 2026-07-03. Concurrent single-mobile POSTs to
`console.authkey.io/restapi/requestjson.php` return the SAME `LogID` for all
recipients in the same batch. **The CRM must never treat `LogID` as a unique
key**. Always disambiguate with `customer_phone` when matching webhooks.
CR-039 implements this defensively.

### 5.5 State-machine gate order matters
`routers/whatsapp.py` webhook handler must set status-specific timestamps
**after** the `next_status()` gate. Otherwise duplicate/late webhooks overwrite
the original event time. See CR-041 for the pattern.

### 5.6 Hot-reload works
Both backend (uvicorn --reload via supervisor) and frontend (webpack dev
server) auto-reload on file save. `sudo supervisorctl restart` is only
needed for `.env` changes or new pip/yarn packages.

### 5.7 Testing agent conventions
`testing_agent_v3_fork` output goes to `/app/test_reports/iteration_{n}.json`.
The agent writes test files to `/app/backend/tests/`. Existing test file:
`test_cr039_webhook.py` (11 tests). Add to this file for related webhook tests
in future.
